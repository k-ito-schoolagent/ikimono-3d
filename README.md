# いきもの3D — Living Anatomy Lab

**https://k-ito-schoolagent.github.io/ikimono-3d/**

動物・ヒト・昆虫の**からだと臓器のはたらき**を、3Dで動かして学ぶ高校生物向けの日本語教材集です。どのデモも、画面の裏で動いている**計算モデルとその前提を明示し、テストで検証**しています。授業ではプロジェクターに映して、時間をゆっくりにしたり、断面にしたりしながら「いま何が起きているか」を一緒に見るのがおすすめです。

**だれでもデモを追加できる、オープンなプロジェクトです。** 授業で見せたい臓器や生き物の仕組みを、1ページのデモとして足してください。GitHub がはじめての方の、issue やプルリクエストの練習にも使ってください。→ [参加のしかた](CONTRIBUTING.md)

姉妹プロジェクト: [FORM — Interactive Science Lab](https://github.com/k-ito-schoolagent/tech-demo)（機械と半導体）、[戦国合戦 3D俯瞰デモ](https://github.com/k-ito-schoolagent/sengoku-3d)（実際の地形の上の合戦）。

### これからつくるもの（予定）

腎臓のネフロン／昆虫の開放血管系と気管系／ニューロンの活動電位／筋収縮（滑り説）／肺のガス交換／脊椎動物の心臓の比較（魚類・両生類・爬虫類・鳥類と哺乳類）。「これも見たい」は [issue](https://github.com/k-ito-schoolagent/ikimono-3d/issues/new/choose) でリクエストしてください。

操作：ドラッグで回転、スクロール・ピンチで拡大縮小。ドラッグを使わない視点ボタン・左右回転・拡大縮小ボタンもあります。部位は3Dをクリックするか、側面のボタンで選べます。スライダーはキーボードでも操作できます。動きを減らすOS設定では停止状態から始まります。`H` で UI を隠して画面録画ができます。

## 動かす

```sh
npm install
npm run dev        # 開発用サーバー（表示された URL を開く）
npm test           # 計算モデルのテスト
npm run build      # dist/ に書き出し
npm run preview    # ビルド結果を表示
```

Node.js 22 以上を使ってください。

## しくみ

```
demos.json            デモの登録簿（ナビ・一覧ページ・ビルド対象はここから自動でつくられる）
index.html            一覧ページ
<id>.html             各デモのページ（heart / osmosis）
src/<id>.js           各デモの 3D と操作
src/*-model.js        計算モデル（描画から切り離し、node --test で検証）
src/*.test.js         テスト
src/stage.js          3D の舞台（カメラ、光、影、視点ボタン、部位のクリック、ラベル、図面の床）
src/navigation.js     ヘッダーのナビ、ライト／ダーク切り替え、埋め込み表示
src/marching.js       符号付き距離の場から等値面をつくる（マーチングキューブ法）
src/heart-field.js    心臓の形（部屋・内腔・血管を距離の場で定義。断面にすると壁の厚さが出る）
src/heart-*.js        心臓デモの材質・舞台装置・血液の粒・2D表示
scripts/new-demo.mjs  新しいデモの雛形をつくるスクリプト
public/thumbs/        一覧のサムネイル（<デモ>.html?embed&thumb で書き出す）
publish.sh            GitHub にリポジトリをつくって Pages を有効化する
```

どのデモも `?embed` を付けると3Dだけを全画面で表示します。トップページのショーケースは、これを1つずつ埋め込んで自動で回して見せています。

### 使っている技術

- [three.js](https://threejs.org/)（3D 表示。OrbitControls・CSS2DRenderer・RoomEnvironment・RoundedBoxGeometry と、MarchingCubes アドオンの表データを使用）
- [Vite](https://vite.dev/)（開発サーバーとビルド。複数ページ構成）
- [Lucide](https://lucide.dev/)（アイコン）
- Google Fonts: Shippori Mincho（見出し）、Noto Sans JP（本文）、JetBrains Mono（数値・ラベル）
- Node.js の標準テストランナー `node --test`（計算モデルの検証）
- GitHub Actions + GitHub Pages（`main` に取り込まれると、テスト・ビルドのあと自動で公開。プルリクエストではテストとビルドだけ自動で確認）

### 自分のアカウントで公開する（フォークした人向け）

フォークしたリポジトリの Settings → Pages で Source を「GitHub Actions」にすると、`main` に push したときに同じワークフローで `https://<あなたのID>.github.io/ikimono-3d/` に公開されます。`gh` が使えるなら `./publish.sh` でリポジトリの作成から Pages の有効化までを一度に行えます。

## モデルの前提

### 心臓と血液循環

時刻の原点は心室の収縮開始（R 波のころ）、心周期 RR = 60 / 心拍数。心室収縮期は安静時 0.3 秒で、心拍数が上がると `0.3 × (RR / 0.857)^0.6` で短くなる（拡張期はそれ以上に短くなる）。PR 時間は `0.08 + 0.1 × RR`（0.10〜0.20 秒）、興奮から収縮までの電気機械的な遅れ 0.04 秒。心房の収縮は房室弁が開いてから始まり、終わるとすぐ心室が収縮する（1 周期の期の順は 等容性収縮期 → 駆出期 → 等容性弛緩期 → 充満期 → 心房収縮期）。刺激伝導系の表示は 洞房結節 → 心房 → 房室結節 → ヒス束・プルキンエ線維（PR 区間の終わり）→ 心室筋（QRS）。

1回拍出量 = EDV − ESV。安静時 EDV 120 mL・ESV 50 mL。70 bpm を超えると心拍数とともに交感神経の緊張が強くなるとみなして ESV が最大 20 mL 減り、充満の時間が 0.16 秒を切ると EDV が減る（1回拍出量が頭打ちになり、180 bpm では減る）。60 bpm 未満では充満の時間が長いぶん EDV を最大 15 mL 増やす。心拍出量 = 心拍数 × 1回拍出量。大動脈圧は安静時 120/80 mmHg、運動時は収縮期だけ上がる。右心系の圧は左心系の 1/5、容積の変化は左右で等しい。弁は圧力の差で決まる期（房室弁は充満期と心房収縮期、半月弁は駆出期）だけ開く。心電図はⅡ誘導の形を模した合成波形、QT 時間は Bazett の式。

含まないもの: 血管の抵抗と血圧の調節、運動時の静脈還流の増加（Frank–Starling の法則による 1回拍出量の増加）、呼吸の影響、冠状動脈、心臓の捻れる動き、弁の形の個人差。形は部屋の位置関係と壁の厚さの違いが分かるように模式化したもので、解剖図の寸法ではありません。血液の粒の数と速さ、興奮の光の見え方は観察用の誇張です。

### 浸透と細胞（見本）

細胞膜は水だけを通す半透膜とし、体積はボイル＝ファントホッフの関係 `V = Vb + (V0 − Vb) × C0 / C` に従う。濃度は溶けている粒子の総濃度（osmol/L）で表し、等張液 0.3 osmol/L（0.9 % の食塩水に相当）、水が出入りしない部分の割合 0.4（ヒトの赤血球の代表値）。体積は目標値に時定数 1.2 秒の一次遅れで近づき、1.7 倍を超えると溶血とみなす。溶質が膜を通る効果、膜の弾性、赤血球の円盤の形は含みません。

## 検証（npm test）

- 心臓: 各期が順に並び合計が RR になること、1 周期に各期が 1 回ずつ決まった順で現れること、安静時の代表値（心室収縮期 約0.3 s・1回拍出量 70 mL・心拍出量 4.9 L/min・血圧 120/80）、心拍数が上がると拡張期の割合が減ること、心拍出量 = 心拍数 × 1回拍出量、180 bpm で1回拍出量が頭打ちになること、房室弁と半月弁が同時に開かないこと、弁の開閉が圧力の差と一致すること（僧帽弁が開く ⇔ 左心房圧 ≥ 左心室圧、大動脈弁が開く ⇔ 左心室圧 ≥ 大動脈圧）、容積が EDV と ESV の間で連続に変化すること、左右の心室の容積が等しく右心室の圧が 1/5 であること、心電図の P → QRS → T の順と刺激伝導系の順序。
- 浸透: 等張で体積不変、濃度に対する単調性、水が出入りしない部分より小さくならないこと、溶血のしきい値、時間変化の単調収束。
- ページ間移動、主要操作、断面・線画の表示、狭い画面の表示はブラウザで確認。
